# OCTera

Веб-платформа для загрузки изображений (OCT-снимков) и получения аналитического «вердикта» с помощью ML-модели.

## Статус проекта

Есть минимальный backend-скелет (FastAPI) с заглушкой вместо реальной модели — см. раздел "Разработка". Архитектура и часть технологий пока не зафиксированы окончательно, README будет расширяться по мере разработки.

## Идея

1. Пользователь загружает изображение через веб-интерфейс.
2. Изображение анализируется ML-моделью.
3. Пользователь получает результат анализа (вердикт) и может посмотреть историю своих загрузок.

Модель не будет обучаться с нуля — планируется взять готовую предобученную модель и дообучить (fine-tune) её под конкретную задачу. Выбор конкретной модели пока открыт.

## Планируемый стек

- **Бэкенд:** Python + FastAPI — удобен для интеграции с PyTorch/TensorFlow и для дообучения/инференса моделей.
- **ML:** предобученная модель компьютерного зрения, дообучаемая (fine-tuned) под задачу анализа OCT-снимков. Конкретная базовая модель ещё не выбрана.
- **Фронтенд, база данных, хранение файлов:** пока не определены.

## Справочные материалы

В проекте есть подробный research-отчёт по возможной архитектуре платформы, покрывающий:

- варианты стека фронтенда/бэкенда и хранения данных;
- API-контракты (загрузка изображений, получение статуса и результата анализа);
- варианты развёртывания и обслуживания ML-модели (TorchServe, TensorFlow Serving, Triton и др.);
- CI/CD и контейнеризацию;
- стратегию тестирования;
- безопасность, конфиденциальность и соответствие требованиям (GDPR/ПДн);
- наблюдаемость (логи, метрики, алерты, SLO).

Он используется как справочный материал при принятии архитектурных решений, но сам по себе не фиксирует финальный выбор технологий.

## Разработка

### Backend (заглушка вместо реальной модели)

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload
```

Эндпоинты: `POST /api/images/upload`, `GET /api/images/{image_id}/status`, `GET /api/images/{image_id}/result`, `GET /api/health`.

Важно: анализ изображения сейчас — заглушка (случайная метка/confidence), реальная модель ещё не выбрана и не дообучена (см. `docs/PLAN.md`, этапы 1 и 3). Хранение — в памяти процесса, без БД.

Тесты: `.venv/bin/pytest tests/`.
