# OCTera

Веб-платформа для загрузки изображений (OCT-снимков) и получения аналитического «вердикта» с помощью ML-модели.

## Статус проекта

Backend (FastAPI) подключён к реальной модели анализа OCT-снимков — см. раздел "Разработка". Архитектура и часть технологий пока не зафиксированы окончательно, README будет расширяться по мере разработки.

## Идея

1. Пользователь загружает изображение через веб-интерфейс.
2. Изображение анализируется ML-моделью.
3. Пользователь получает результат анализа (вердикт) и может посмотреть историю своих загрузок.

Модель не обучалась с нуля — используется готовая предобученная модель. Дообучение на собственных данных (при необходимости) — следующий шаг, пока используется как есть.

## Планируемый стек

- **Бэкенд:** Python + FastAPI — удобен для интеграции с PyTorch/TensorFlow и для дообучения/инференса моделей.
- **ML:** [`tomalmog/oct-retinal-classifier`](https://huggingface.co/tomalmog/oct-retinal-classifier) — EfficientNet-B3, дообученная на датасете Kermany под 4 класса: CNV, DME, DRUSEN, NORMAL. Точность 99.6% на тестовой выборке автора. **Лицензия — MIT (коммерческое использование разрешено)**. Компактная (~46 МБ, 11.5M параметров) — инференс на CPU ~2 сек.
- **Хранение:** SQLite (метаданные/результаты) + файлы изображений на диске — для MVP этого достаточно, без внешней БД/облачного хранилища.
- **Фронтенд:** React (Vite) SPA — основной канал доступа к MVP. Telegram-бот планируется как второстепенный канал позже, не блокирует сайт.

## Справочные материалы

В проекте есть подробный research-отчёт по возможной архитектуре платформы, покрывающий:

- варианты стека фронтенда/бэкенда и хранения данных;
- API-контракты (загрузка изображений, получение статуса и результата анализа);
- варианты развёртывания и обслуживания ML-модели (TorchServe, TensorFlow Serving, Triton и др.);
- CI/CD и контейнеризацию;
- стратегию тестирования;
- безопасность, конфиденциальность и соответствие требованиям (GDPR/ПДн);
- наблюдаемость (логи, метрики, алерты, SLO).

Он используется как справочный материал при принятии архитектурных решений, но сам по себе не фиксирует финальный выбор технологий.

## Открытые вопросы

- Нужно ли дообучение модели на собственных данных, или текущего качества (99.6% на тестовой выборке автора модели) достаточно для MVP? Модель не валидирована клинически и обучена на одном типе OCT-аппарата. (В процессе решения.)
- Кто основной целевой пользователь — пока не определено, MVP открыт для любого пользователя.

## Разработка

### Backend

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload
```

Эндпоинты: `POST /api/images/upload`, `GET /api/images/{image_id}/status`, `GET /api/images/{image_id}/result`, `GET /api/health`.

При первом вызове анализа веса модели (~46 МБ) скачиваются с Hugging Face и кэшируются в `~/.cache/octera-model/` — первый запрос занимает несколько секунд, дальше — доли секунды.

Результаты анализа хранятся в SQLite (`backend/data/octera.db`), сами изображения — в `backend/data/uploads/` — данные переживают перезапуск сервера. Эта папка не коммитится в git (см. `.gitignore`).

Тесты: `.venv/bin/pytest tests/` (реальная модель в тестах подменяется заглушкой — тесты быстрые и не требуют сети).

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Открыть `http://localhost:5173` (backend должен быть запущен на `http://localhost:8000` — CORS уже настроен для локальной разработки).

Что есть в MVP: загрузка снимка → результат с пояснением диагноза и дисклеймером ("не медицинский диагноз") → история последних загрузок (хранится только в `localStorage` браузера, без аккаунтов/авторизации — их пока нет на backend).

`npm run build` — продакшен-сборка.
