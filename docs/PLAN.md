# План разработки OCTera

Высокоуровневый план по этапам. Без жёстких сроков — уточняется по ходу разработки. Мы не обучаем модель с нуля: берём готовую предобученную модель компьютерного зрения и дообучаем (fine-tune) её под задачу анализа OCT-снимков.

## 1. Выбор базовой модели и данных — сделано
Выбрана модель [`tomalmog/oct-retinal-classifier`](https://huggingface.co/tomalmog/oct-retinal-classifier) (EfficientNet-B3) — уже дообучена на датасете Kermany под 4 класса (CNV/DME/DRUSEN/NORMAL), точность 99.6% на тестовой выборке автора, использовать как есть без своего обучения. Лицензия — MIT, коммерческое использование разрешено. Компактная (~46 МБ) и быстрая (~2 сек/снимок на CPU).

(Ранее была выбрана `bitfount/RETFound_MAE_OCT_CNV_DME_DRU` — отказались из-за лицензии CC BY-NC 4.0, запрещающей коммерческое использование, и медленного инференса на CPU (15-17 сек/снимок).)

## 2. Backend-скелет (FastAPI) — сделано
Поднято базовое FastAPI-приложение с эндпоинтами загрузки изображения, проверки статуса обработки и получения результата.

## 3. Интеграция модели — сделано, дообучение под вопросом
Реальный инференс выбранной модели подключён к backend вместо заглушки. Модель используется как есть, без собственного дообучения — если качества (99.6% на тестовой выборке автора, не валидировано клинически) окажется недостаточно на реальных данных, дообучение на своих данных можно вернуть в план отдельным шагом.

## 4. Хранение данных
Развернуть БД для метаданных (пользователь, время загрузки, статус, результат) и хранилище файлов изображений. Связать их с backend-эндпоинтами.

## 5. Frontend (MVP)
Минимальный интерфейс: форма загрузки изображения и отображение результата анализа. Без лишнего функционала — только рабочий путь пользователя.

## 6. Тестирование
Юнит-тесты backend-логики и базовый интеграционный тест полного цикла: загрузка → анализ → получение результата.

## 7. Деплой MVP
Развернуть в тестовом окружении (staging), провести smoke-тест, собрать обратную связь перед дальнейшей доработкой.

## 8. Безопасность и приватность
Перед выходом в продакшен: HTTPS, аутентификация и — если снимки являются медицинскими/персональными данными — их защищённое хранение и обработка.
